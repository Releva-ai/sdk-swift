    Harness facts

    • Credentials go in Settings at runtime (access token, realm, endpoint override, profile ID). SDK is off until token and profile ID are set.
    • Only Home sends a page token (). Cart, Checkout, Success send screenToken: nil → the backend writes no pageView for them.
    • Banners render on Home only (selector #home-content). Stories and NPS are app-wide.
    • Deep links: myapp://consumer.app/{home|cart|checkout|product/<id>|inbox|inbox/<id>}. The scheme is not registered in the shipping plist; only push-driven navigation works.
    • Debug build only for RelevaSDK: logs. Sandbox APNs (aps-environment = development), Firebase project releva-248016.

    Harness bugs that fake SDK failures

    1. Double banner init (AppState.swift:332) could duplicate impressions. Did not reproduce in run 1; keep counting Banner impression tracked lines.
    2. trackEngagement(.opened) fires on every remote delivery, silent ones included → spurious callback GETs.
    3. Two permission prompts can race.
    4. Checkout request is fire-and-forget right before navigation.
    5. Firebase proxy key was in an orphaned plist; fixed 2026-09-02 (now in the shipping Info.plist).
    6. Inbox list crash: InboxView.stripHtml runs the HTML importer inside a view update (run 4, SIGABRT). Use the regex fallback.
    7. Checkout deep link shows a blank screen: the String navigationDestination is not reachable from the deep-link push (run 4).

    SDK ⇄ backend mismatches found while writing this plan

    1. Engagement events (PUSH-03, PUSH-06): delivered, opened and clicked all GET the same callbackUrl; the backend records each as pushNotificationClick. The GET carries the default CFNetwork user agent and click-tracker.js drops UA unknown, so clicks may vanish entirely.
    2. Test pushes never record clicks: no campaign id. Stats rows need a real campaign.
    3. Token-less screens write no pageView (TRK-02). Expected; the client guide must say so.
    4. Story stats (STO-08): SDK sends the story token, admin aggregates on the numeric id.
    5. NPS opens (NPS-11): backend counts npsOpen, SDK never sends it.
    6. Action button (PUSH-05): resolved in run 3, the extension-registered RELEVA_DYNAMIC category renders the button and yields clicked.
    7. Bot filter (SET-04): resolved in run 1, the backend parses RelevaSDK-iOS/5.0.0 as a browser, not a bot.
    8. Firebase proxy vs SwiftUI (TOK-02): with FirebaseAppDelegateProxyEnabled at its default, Firebase's swizzling under @UIApplicationDelegateAdaptor swallowed the APNs callback and push never registered. NO in the shipping Info.plist fixed it; the SDK README must say so for SwiftUI integrators.
